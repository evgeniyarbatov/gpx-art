# Architecture

## End-to-end flow

```
[private] repo ── make [private]
        │
        ▼
data/parquet/{android,casio,strava}/<city>.parquet
        │
        ▼
  select tracks ── random (make random) or DTW diversity (make dtwselect)
        │
        ▼
     gpx/          working set (one-track .parquet files)
        │
        ▼
  gpx-art.py       for each track × each style
        │
        ├─ style function → matplotlib figure
        ▼
   images/         <style>-<track>.png
```

1. Clone or update `[private]` into the data directory.
2. Sample tracks from the city parquet files into `gpx/` (random or DTW).
3. Optionally preview the working set with `plot-gpx.py`.
4. Render each track with every registered style in `gpx-art.py`.
5. Write PNGs to `images/`.

## Components

| Path | Role |
|---|---|
| `scripts/gpx-art.py` | Main generator: style registry, rendering |
| `scripts/sample-tracks.py` | Random sample from a parquet (or GPX) library |
| `scripts/dtw-select.py` | Diverse track selection via FastDTW |
| `scripts/plot-gpx.py` | Visual grid preview of the working set |
| `scripts/utils.py` | Shared track listing, parquet/GPX load, sample/write |
| `gpx/` | Working one-track parquet inputs |
| `images/` | Generated PNG outputs |
| `Makefile` | Orchestrates checkout, select, plot, render, test |

## Style system

Styles are plain Python functions registered with a decorator:

```python
@style("scaffold")
def scaffold(lons, lats):
    # draw with matplotlib …
    return fig, bg_color
```

- `STYLES` maps name → callable.
- Each style receives longitude/latitude arrays and returns a figure plus background color.
- `create_art` looks up the style, draws the track, and saves the PNG.
- New styles are added by defining another `@style(...)` function in `gpx-art.py`; no central switch statement.
- `extract_style_source` parses `gpx-art.py` with the AST to pull the full source of a single `@style` function by name.

Path helpers (`essence_path`, `flow_path`, `gap_mask`, ink strokes, palettes, etc.) are shared utilities used by many styles.

## Track selection

**Random** (`make random` / `sample-tracks.py`): load every track from the parquet tree, pick `NUMBER_OF_GPX` of them, write one-track parquet files into `gpx/`.

**DTW** (`make dtwselect` / `dtw-select.py`):

1. Load all tracks from the parquet tree (city files are multi-track).
2. Drop tracks shorter than 10 km.
3. Downsample and normalize trajectories.
4. Greedily pick a diverse set maximizing FastDTW distance between selected tracks.
5. Write winners as one-track parquet files into `gpx/`.

A city parquet is a bundle of tracks (`name`, LineString `geometry`, `city`). Source is the parent folder (`android`, `casio`, `strava`). Working-set filenames include source, city, row index, and name because many rows share a name like `Sport`.

## Data layout

- Default source is `[private]` checked out to `$(DATA_DIR)/[private]` (`git@github.com:evgeniyarbatov/[private].git`).
- `SOURCE_DIR` defaults to that checkout's `data/parquet` tree. A local GPX folder still works if you override `SOURCE_DIR`.
- Tracks in `[private]` are already RDP-simplified at 10 m.
- `gpx/` and `images/` are working directories regenerated by Make targets.
